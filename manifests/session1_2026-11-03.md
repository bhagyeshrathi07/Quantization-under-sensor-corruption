# GPU session 1 on the replacement host (November 3, 2026, semester week 9)

## Host

The October host (Vast.ai m:3752, Norway, 300 W cap) destroyed the stopped instance between October 15 and November 3, so `/workspace` was rebuilt from `scripts/vast_setup.sh` on a new host: Vast.ai offer m:11851 (container C.59020096), Spain, RTX 4090 24 GB at the stock 450 W power limit, driver 615.71.09 (CUDA 13.4), 23 CPU cores, 183 GB RAM limit, 128 GB disk, about 4 Gbps network. Setup to first server took 25 minutes; the clean nuScenes keyframes took 45 minutes (ten tarballs at about 20 MB/s from CloudFront to this host).

Software installed fresh: vLLM 0.33.0, torch 2.14.0+cu130, transformers 5.20.2 (pilot was 0.31.0 / 2.13.0 / 5.17.0). Pinned in `manifests/requirements_frozen.txt`. The quantization venv (`.venv-quant`) has llm-compressor 0.15.0, compressed-tensors 0.20.1, transformers 5.21.0, torch 2.14.1, torchvision 0.29.2.

**Consequence (PROTOCOL section 2 host rule):** every profiling session must run on this host. The October pilot latency (LowLight, 20 questions, 300 W cap, `--gpu-memory-utilization 0.9`) is superseded and stays labeled pilot.

## Verified for the first time

- `--kv-cache-memory-bytes 2147483648` is accepted by vLLM 0.33: "reserved 2.0 GiB memory for KV Cache as specified by kv_cache_memory_bytes config", 37,440 KV tokens, 9.14× concurrency at 4096 tokens, both precisions.
- Streaming time-to-first-token path in `07_profile.py` works (`stream_options.include_usage` honored).
- All 1200 clean nuScenes images present (`download_drivebench.py --verify`); corruption directory has all 15 types, 1800 jpg each.
- `quantize_awq.py` runs end to end in the separate venv after two fixes: torchvision added to the `quant` extra (the Qwen2.5-VL processor imports it), and the processor's batch dimension kept on `input_ids` (the rope index reads `input_ids.shape[1]`). llm-compressor warns "28 mappings were skipped due to incompatible shapes": one per decoder layer, the `v_proj -> o_proj` balance that cannot apply under grouped-query attention (4 KV heads versus 28 query heads); expected.

## Own INT4 checkpoint (`checkpoints/qwen2.5-vl-7b-awq-w4a16-g128` on the host, 6.5 GB; `manifests/quantize_qwen2.5-vl-7b-awq-w4a16-g128.json`)

Built from the pinned base revision with llm-compressor 0.15.0: AWQ, W4A16 asymmetric, group size 128, `Linear` targets, vision tower / embeddings / `lm_head` kept at BF16; calibration = all 107 eligible calibration-split questions (17 scenes; 17 behavior MCQ, 17 perception MCQ, 17 perception VQA, 51 planning VQA, 5 prediction VQA), rendered as the runs render them (system prompt, selected views, `max_pixels` 200704, clean images). 29 sequential stages, 488 s, 11 GB GPU peak. Saved as compressed-tensors; vLLM serves it with `--quantization compressed-tensors` (6.67 GiB weights, same 2 GiB KV cache).
